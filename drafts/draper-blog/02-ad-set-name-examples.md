# Ad Set Name Examples That Answer Real Questions

Here's an ad set name example you can copy today: `2026-10-12_Broad-US_LC_C14-SleepFix`. That's launch date, audience, bid type, and the concept under test, in that order.

Most naming guides stop at the pattern. The part they skip is why each field is there. **A field earns its place in a name only when you can say which question it answers.** If you can't, it's clutter, and clutter is how a naming convention dies by week three.

Below are worked patterns for campaigns, ad sets, and ads, the two places experienced buyers disagree, and what to stop doing.

## What should an ad set name include?

An ad set name should record how and when you're buying: the launch date, the audience, the bid type, and the concept if you run one concept per ad set.

We call the rule behind it **question-first naming: before a field goes into a name, you write down the report it will let you pull.** Here's how the common fields pass the test:

| Field | The question it answers |
|---|---|
| Launch date | Which weekly batch is this, and does it join to my tracker? |
| Audience | Is broad beating my stacked audiences? |
| Bid type | Is cost cap earning its keep against lowest cost? |
| Concept | Which idea won, across every ad set it ran in? |
| Creator | Who's worth rebooking? |
| Format | Are statics carrying more spend than video? |
| Destination | Product page or advertorial? |

Fields that fail the test, like "final," "NEW," or the buyer's initials, never make it in.

## Campaign, ad set, and ad name examples

Experienced practitioners agree on the job of each level. The campaign holds structure, the ad set holds the buying decision, and the ad holds everything about the creative.

**Campaign names** carry type, objective, location, and offer:

```
PRO_Sales_US_20OFF
EXIST_Sales_US-CA_Bundle
```

**Ad set names** carry date, audience, bid type, and concept:

```
2026-10-12_Broad-US_LC_C14-SleepFix
2026-10-12_Broad-US_CC_C15-Travel
```

**Ad names** come in a lean and a rich version:

```
Lean:  VID_UGC_SleepFix_NoMoreAlarm_PDP
Rich:  C14_VID_UGC_Kai_SleepFix_ProblemAware_H2_v3_W42_PDP
```

Use codes for closed lists (bid type, format, destination) and words for open ones (concept, creator). Then publish the key where the whole team can find it.

## Split 1: how many fields should a name carry?

Experienced buyers split on this. One camp keeps names lean, about five fields per level, often in short codes. It wins for small teams where the media buyer types every name by hand.

The other camp runs 7 to 12 fields, including awareness stage, creator, product, and test type. It wins when a creative strategist and a production pipeline sit behind the account and the name doubles as the brief ID. But this camp has a telling history. Practitioners in it report that adding fields made their own teams use the convention less, and their templates have shrunk over time.

**Our take: if people type names by hand, cap the ad name at five to seven fields.** Go richer only when the name is generated from a sheet, a formula, or a tool, and every field passes the question test.

Here's the math on why typing matters. Say a team launches 40 ads a week (hypothetical) and 1 in 10 hand-typed names drops or misspells a field. That's 4 ads a week that fall out of every pivot table, or 52 a quarter. Your best ad could be one of them.

## Split 2: does the concept live in the ad set name or the ad name?

One camp puts the concept in the ad set name, because their testing system runs one concept per ad set. It's clean while the ad stays where it was born.

The other camp puts everything that describes the creative on the ad, and treats campaign and ad set names as secondary.

**Our take: put the concept in the ad name, always.** Add it to the ad set name too if you run one concept per ad set. The reason is what happens to winners. When you move a winning ad into a scaling campaign by its post ID, the ad set name stays behind. The ad name travels with it into every export. That's how we test, as covered in our guide to [Facebook ads testing](/blog/facebook-ads-testing).

## What to stop doing

The panel agrees on five habits to drop:

- **Default names:** "New ad" and stacked "- Copy - Copy" chains hide every pattern you'd want to find.
- **Mixed conventions:** one account, one convention, used by the freelancer, the agency, and the in-house team alike.
- **Renaming live ads:** it breaks reporting continuity and the join to outside trackers. Apply the convention going forward and back-fill old names in a side table.
- **Funnel-stage labels:** TOF and BOF tags go stale the moment a campaign's job changes.
- **Expecting a lift:** naming fixes reporting, not performance.

One more caution. A name is not proof of variety. Ten ads tagged as ten concepts can still look like the same ad, so lay your top creatives side by side before you trust the labels. Our post on [ad fatigue](/blog/what-is-ad-fatigue) covers what happens when they're all the same ad.

Some practitioners also add a one-character prefix for any tactic they'll want to total later, such as ads run from a creator's page. It turns "have we really tested this?" into a filter with a spend figure. (More on those in [whitelisting vs partnership ads](/blog/whitelisting-vs-partnership-ads).)
